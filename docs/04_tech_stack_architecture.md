# 04. 기술 스택 및 아키텍처 분석

이 문서는 프로젝트의 성능, 안정성, 확장성을 위해 채택된 기술 스택과 헥사고날 아키텍처 설계 원칙을 상세히 분석합니다.

## 🛠️ 핵심 기술 스택

### 1. 언어 및 런타임: Rust & Tokio
- **성능**: Rust는 가비지 컬렉션 없는 제로 비용 추상화를 제공하여 금융 데이터 처리 시 지연 시간을 최소화합니다.
- **비동기 처리**: `tokio` 런타임을 통해 수많은 WebSocket 연결과 DB I/O 태스크를 경량 스레드(Green Threads)로 효율적으로 관리합니다.

### 2. 시계열 데이터베이스: QuestDB
- **고속 쓰기**: InfluxDB Line Protocol(ILP)을 통해 초당 수만 건 이상의 데이터를 지연 없이 저장합니다.
- **SQL 지원**: 시계열 특화 쿼리를 표준 SQL 형식으로 수행할 수 있어 데이터 분석 및 백테스트 데이터 인출에 유리합니다.

### 3. 정밀 연산: `rust_decimal`
- **금융 정확성**: 부동 소수점 오차를 방지하기 위해 모든 가격, 수량 계산에 128비트 정밀도의 `Decimal` 타입을 사용합니다.

## 🔄 핵심 설계 원칙: 헥사고날 아키텍처

본 프로젝트는 의존성 역전 원칙(DIP)을 극대화한 **헥사고날 아키텍처(Ports & Adapters)**를 따릅니다.

### 1. 관심사의 분리 (Separation of Concerns)
- **도메인 중심 설계**: 비즈니스 로직(전략, 주문 처리 규칙 등)은 외부 라이브러리나 DB 설정에 의존하지 않고 `src/domain`에 고립되어 있습니다.
- **교체 가능한 어댑터**: 바이낸스 API에서 타 거래소 API로 변경하거나, QuestDB에서 다른 시계열 DB로 변경할 때 도메인 로직을 수정할 필요 없이 어댑터만 새로 구현하면 됩니다.

### 2. 테스트 용이성 (Testability)
- **Mocking**: 포트(Port) 인터페이스를 통해 실제 거래소나 DB 없이도 도메인 로직을 검증할 수 있습니다.
- **백테스트 활용**: 실거래 코드(`trader`)와 백테스트 코드(`backtest`)가 동일한 도메인 모델과 포트를 공유하므로, 전략 검증의 신뢰도가 높습니다.

## 🚀 성능 최적화 전략
- **Zero-Copy Deserialization**: `serde`를 활용하여 메모리 복사를 최소화하며 JSON을 파싱합니다.
- **MPSC Buffering**: 생산자(데이터 수집)와 소비자(데이터 저장) 사이에 비동기 채널을 두어 I/O 병목이 수집 태스크에 영향을 주지 않도록 설계되었습니다.
- **Batching Strategy**: DB 쓰기 시 개별 요청이 아닌 설정된 단위(로우 수 또는 시간)로 모아서 전송함으로써 네트워크 및 디스크 오버헤드를 줄입니다.
